# v0.0.4

目标：在不破坏现有“行程生成 + Agent 编排 + 联网 RAG”的前提下，引入可复用的第三方能力，补齐“可持续知识库 + 可配置编排 + 可扩展 UI”的工程化短板，让产品具备更强的可扩展性与交付效率。

## 背景与现状（v0.0.3）
- 已有 RAG：偏“联网检索 + 临时向量库”的链路，主要服务于单次查询的证据补充，执行前会清空向量库上下文，不具备持久化知识库能力
- 已有编排：基于 LangGraph 的顺序编排（Planner → Checker → Optimizer → Map/RAG），具备事件/快照与 UI 调试面板
- 已有 UI：Streamlit 为主，适合快速迭代与调试，但对产品化 UI/权限/多端适配能力有限，需优先迁移为 React + Vite

## 核心需求

### P0：React + Vite 单 UI（最高优先级）
目标：替换 Streamlit，全面迁移为 React + Vite，优先保障更好的调试体验与产品化 UI。

建议的范围收敛（避免一次做太重）：
- v0.0.4 直接以 React + Vite 作为唯一 UI 入口，不再保留 Streamlit
- 先完成 CSR 版本，SSR 作为后续优化项
- 需要优先完成与后端 API 的端到端联通（行程生成/会话/知识库）

UI 框架选型（Ant Design 生态）：
- Ant Design（antd）：基础组件与设计体系，作为主 UI 组件库 https://ant.design/docs/react/introduce/
- ProComponents：面向中后台的高阶组件（ProTable/ProForm/ProLayout），用于复杂表单与数据列表 https://procomponents.ant.design/en-US/docs/intro/
- Ant Design X：AI 交互与对话式 UI 组件与规范 https://x.ant.design/
- Ant Design Charts（AntV）：图表与可视化组件库 https://ant-design-charts.antgroup.com/en
- Ant Design Mobile：移动端 Web 组件库（如需移动端适配） https://mobile.ant.design/

验收标准（最小可用）：
- 有稳定的后端 API：行程生成、会话列表、知识库检索/导入（至少覆盖核心链路）
- React + Vite 前端能完成：输入 → 生成行程 → 展示行程（地图可先用 iframe/图片占位）

### P1：可持续知识库 + 证据引用
目标：把“爬虫数据 + 用户上传文档”统一纳入可持久化知识库，并在行程生成链路中可控注入证据。

范围（功能性）：
- 数据源
  - 网页数据：支持将现有“联网检索抓取结果”或“指定 URL 列表”入库
  - 用户文档：支持上传 PDF/Markdown/Docx/纯文本等常见格式（至少先覆盖：PDF/Markdown/纯文本）
- 知识库/数据集
  - 支持创建/删除知识库（或数据集），并支持为一次对话/一次行程选择 1~N 个数据集参与检索
  - 支持对入库内容做元数据标注：来源、时间、标签（目的地/主题/语言）、所属用户/会话（为多用户做准备）
- 检索与证据
  - 支持相似度检索 TopK 与重排（可选），并返回可追溯引用（source/title/片段）
  - 支持“证据预算”控制（长度/条数），避免上下文溢出
- 与行程生成的集成
  - 生成/修改行程时，可选择性开启“知识库检索增强”，并把证据以结构化方式注入到生成 Prompt

可选实现路径（两条都算达标）：
- Path A：集成 RAGFlow 作为外部知识库服务（通过 API 入库/检索）
- Path B：沿用现有 Chroma，但补齐“持久化 collection + 多数据集 + 文档上传解析 + 统一检索接口”

验收标准（最小可用）：
- 能创建至少 1 个知识库并成功导入：1) 10+ 条网页内容 2) 1 个 PDF（或 1 个 Markdown）
- 同一知识库可在多次会话中复用，重启服务后仍可检索到
- 行程生成在开启知识库后：输出中能体现至少 3 条来自知识库的事实性信息，并能给出来源引用


## 必要性与可行性评估
### 总体判断
- “知识库持久化 + 文档上传”有必要：这是从“演示型 RAG”走向“可复用产品”的关键能力；且与当前“联网检索临时向量库”属于互补，不是重复建设
- “Dify 编排”不一定必要：当前已具备 LangGraph 编排与工具协议，Dify 的价值主要在“可视化配置/运营效率/多人协作”；若团队规模较小或迭代仍偏研发驱动，可先走“内部配置化”，预留 Dify 对接接口
- “React + Vite 单 UI”是最高优先级：Streamlit 不再保留，优先完成产品化 UI 形态与调试效率提升

### 对标主流旅游规划产品的常见需求
- AI 行程生成与可编辑的日程：Tripadvisor Trips 提供 AI 行程生成与可保存/编辑/分享的日程能力 [1](https://www.tripadvisor.com/Trips) [2](https://tripadvisor.mediaroom.com/Tripadvisor-launches-AI-powered-travel-planning-product)
- 多人协作与实时同步：Wanderlog 支持多人协作、实时同步、共享行程 [3](https://apps.apple.com/us/app/wanderlog-travel-planner/id1476732439)
- 预订导入与行程自动整理：Wanderlog 支持邮件导入预订；TripIt 支持转发确认邮件自动整理行程 [3](https://apps.apple.com/us/app/wanderlog-travel-planner/id1476732439) [4](https://www.tripit.com/web) [5](https://www.tripit.com/web/free/how-it-works)
- 预算与费用管理：Wanderlog 支持预算、记账、分摊 [3](https://apps.apple.com/us/app/wanderlog-travel-planner/id1476732439)
- 地图与路线优化：Wanderlog 提供地图视图与路线优化；Roadtrippers 提供多停靠点路线规划、离线地图与协作 [3](https://apps.apple.com/us/app/wanderlog-travel-planner/id1476732439) [6](https://apps.apple.com/us/app/roadtrippers-trip-planner/id944060491)
- 预订与价格联动：Trip Planner AI 强调实时价格与机酒/活动预订连接 [7](https://tripplanner.ai/)
- 离线可用与行前提醒：Wanderlog/TripIt 均提供离线行程访问或提醒能力 [3](https://apps.apple.com/us/app/wanderlog-travel-planner/id1476732439) [4](https://www.tripit.com/web)

### 与当前项目（v0.0.1~v0.0.3）相比的缺口
- 协作与共享：缺少协作编辑、权限与分享链接等能力（规划转入 v0.0.5）
- 预订导入与自动整理：缺少从邮件/文件导入机票酒店订单并自动生成行程的能力（规划转入 v0.0.5）
- 预算与费用管理：缺少预算设置、费用追踪与分摊功能（规划转入 v0.0.5）
- 路线优化与多停靠点能力：缺少针对跨城市/自驾多停靠点的路线优化与里程时间评估（规划转入 v0.0.5）
- 预订/价格联动：缺少机票/酒店/门票的比价与直连预订能力（规划转入 v0.0.5）
- 离线可用与行前提醒：缺少离线访问、提醒与行前通知（规划转入 v0.0.5）

### 主流产品未充分覆盖的用户痛点（可作为差异化）
- 可验证的证据引用与可控证据预算：强调可追溯来源与可控上下文长度，提升可解释性与可信度
- 可持续知识库与私有数据接入：支持用户文档/网页入库并跨会话复用，满足深度研究型旅行需求
- 可配置编排与模型可切换：支持本地/云端模型与可配置流程，满足不同成本与隐私诉求

## 可落地的开发步骤
### 1. 现状盘点与接口清单
- 盘点现有后端能力与 API：行程生成、会话列表、知识库相关能力
- 固化最小接口契约：请求/响应结构、错误码、鉴权方式
- 输出前后端对接清单与优先级（先保证行程生成与知识库检索链路）

### 2. React + Vite 基础工程搭建
- 基于 Vite 初始化前端工程，确定目录结构与路由规划
- 引入 Ant Design 生态（至少 antd），保留 ProComponents/Ant Design X 作为后续扩展
- 搭建基础页面壳：导航、会话入口、行程生成入口

### 3. 行程生成核心链路联通
- 完成输入表单：目的地/天数/偏好等最小字段
- 对接行程生成接口：提交 → 轮询/流式接收（按后端能力选一）
- 完成结果展示：日程列表/概要信息，地图先用占位 iframe/图片

### 4. 知识库最小闭环（Path A 或 Path B 二选一）
- 创建/删除知识库能力打通
- 支持导入网页内容（URL 列表/爬虫结果入库）
- 支持上传文档（先覆盖 PDF/Markdown/纯文本）
- 统一检索接口并返回可追溯引用字段（source/title/片段）

### 5. 行程生成集成知识库检索
- 前端支持选择 1~N 个知识库参与检索
- 后端注入证据到生成 Prompt，并支持证据预算控制
- 输出中展示引用来源，满足可解释性要求

### 6. 关键验收与回归
- 前后端端到端联通：输入 → 生成 → 展示
- 知识库复用验证：重启服务后可检索
- 行程生成结果包含至少 3 条来自知识库的事实性信息并标注来源
