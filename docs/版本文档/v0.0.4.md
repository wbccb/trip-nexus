# v0.0.4 需求文档

## 版本目标
完成“生成体验 + 可编辑 + 可解释”的核心闭环，在 React + Vite 单 UI 已完成的基础上，形成可交付的 AI 行程规划 MVP。

## 核心价值主张
- 生成体验：流式生成、进度可视化、可取消与可重试
- 可编辑：行程项增删改、顺序调整、局部重生成
- 可解释：推荐理由、数据来源、证据引用

## 范围与边界
- 本版本聚焦输入 → 生成 → 展示 → 编辑 → 再生成的闭环
- 不做预订与支付、多⼈协作与分享、复杂预算管理、离线可用与提醒（规划到 v0.0.5）

## 背景与现状（v0.0.3）
- **RAG 能力（知识获取）**：已实现“联网检索 + 临时向量库”链路，用于获取非结构化信息（如景点评价、游记攻略），但在每次生成后即被清空，无法复用。
- **Function Call（工具执行）**：已集成 `weather`、`geo`、`poi` 等基础工具，用于获取结构化数据（如经纬度、天气数值），直接服务于行程生成的硬约束。
- **编排架构**：基于 Plan-and-Execute 模式（Planner → Checker → Optimizer → Map/RAG），支持事件回溯与快照。
- **UI 现状**：React + Vite 单页面已完成基础对接，Streamlit 作为调试工具保留但不再作为用户入口。

### FunctionCall vs RAG
**技术原理与分工：**
1.  **Function Call (工具/手)**：负责**结构化、确定性数据**的获取与执行。
    -   *场景*：获取“东京塔”的准确经纬度、查询“下周一”的天气预报、搜索“附近 500 米”的咖啡馆列表。
    -   *局限*：API 只能返回预定义的字段（如 rating: 4.5），无法回答“这个咖啡馆适合办公吗？”或“它的拿铁好喝吗？”等非结构化问题。
2.  **RAG (知识/脑)**：负责**非结构化、定性信息**的检索与增强。
    -   *场景*：查找“东京小众赏樱地”的游记推荐、获取“环球影城排队攻略”、回答“为什么这个景点值得去？”（基于真实评论）。
    -   *价值*：为行程生成提供**上下文证据**（Evidence），让 AI 知道 *为什么* 推荐这个地方，而不仅仅是 *哪里* 有这个地方。
3.  **v0.0.4 的知识库升级**：
    -   目前的 RAG 是“用完即扔”的（临时向量库）。
    -   v0.0.4 将支持**持久化知识库**，允许用户上传 PDF/Markdown（如“我的 2023 旅行计划.pdf”或“公司团建手册”）。Function Call 无法直接读取这些私有文件，必须通过 RAG 索引后才能被 AI 检索利用。

## 竞品调研与差距分析 (Gap Analysis)
通过对比行业标杆（携程/飞猪）与 TripNexus 现有版本（v0.0.1-v0.0.3），明确 v0.0.4 的核心追赶目标。

| 核心维度 | 行业标杆（携程/飞猪/马蜂窝） | TripNexus 现状 (v0.0.1-v0.0.3) | 差距分析 (Gap) |
| :--- | :--- | :--- | :--- |
| **交互形态** | **流式卡片 + 地图联动**<br>对话即生成结构化卡片，地图实时打点，支持点击卡片跳转/预订。 | **对话框 + 静态地图**<br>v0.0.3 仅实现后端流式，前端仍为 Iframe 割裂渲染；缺乏组件化交互。 | **高**：缺乏原生流式渲染与组件化交互，体验割裂。 |
| **可编辑性** | **所见即所得 (WYSIWYG)**<br>支持拖拽排序、定点修改（换酒店/换景点）、一键调整预算。 | **对话式修改 (Blackbox)**<br>仅支持通过 Prompt 触发全量重生成，无法微调；缺乏“撤销/重做”。 | **极高**：修改成本高，无法满足精细化规划需求。 |

| **决策辅助** | **多维决策因子**<br>提供“预算管理师”、“拥挤度预测”、“真实评价聚合”。 | **单一文本推荐**<br>v0.0.3 引入 RAG Evidence 但仅展示文本摘要，缺乏结构化决策因子。 | **高**：缺乏辅助决策的量化指标（价格/耗时/评分）。 |


## 核心需求与优先级

**Gap 追赶策略：**
- 针对**交互形态**：废弃 Streamlit，全面转向 **React 单页应用**，实现结构化卡片即时上屏与地图联动。
- 针对**可编辑性**：引入“拖拽排序 (Drag & Drop)”与“所见即所得”编辑，降低修改成本。
- 针对**决策辅助**：在推荐理由中增加结构化标签（评分/类型/耗时），弥补数据短板。

### P0：Agent 编排架构升级（LangGraph）
**现状：** 项目已引入 `langgraph` 依赖并在调研文档中验证了 PoC，但核心调度仍基于自研 `Scheduler` (src/agent/scheduler.py) 与 `PlannerAgent`。

**目标：** 将生产环境的 `agent_loop.py` 全面迁移至 **LangGraph 标准实现**，移除自研调度器，统一编排与状态管理。

**升级路径：**
1.  **State 定义迁移**：将 `Plan/Task/SharedContext` (src/agent/plan_models.py) 映射为 LangGraph 的 `TypedDict` State。
2.  **调度器替换**：废弃 `src/agent/scheduler.py`，使用 `StateGraph` 定义节点 (Planner/Executor) 与边 (Edges)。
3.  **持久化升级**：使用 `langgraph.checkpoint` 替换原有的 `SnapshotStore`，实现开箱即用的断点恢复与历史回放。
4.  **工具层复用**：直接复用 `LlmManager` 中已封装的 LangChain Tools (`@tool`)，无缝接入 Graph 节点。

**功能清单：**
- **LangGraph 迁移**：重构 `PlannerAgent` 为 Graph Node，构建 `StateGraph` 替代 `agent_loop`。
- **子图拆分**：将规划（Planner）、执行（Executor）、反思（Reflector）拆分为独立的 SubGraph，支持更灵活的编排。
- **Human-in-the-loop**：利用 LangGraph 的 `interrupt` 机制，在关键决策节点（如预算超支、行程冲突）引入人工确认。

**验收标准：**
- 成功运行完整的行程生成流程，且状态转换在 LangSmith 或本地日志中可观测。
- 支持在任意节点暂停并恢复执行（利用 Checkpoint）。
- 实现至少一个 Human-in-the-loop 场景（如：工具调用失败时请求用户干预）。

### P0：生成体验与流式协议升级
**目标：** 在 React 中重构流式生成体验，废弃 Streamlit，构建基于 SSE 的统一流式协议，实现“对话即生成结构化卡片”与高可靠的断线重连。

**功能清单：**
- **统一流式协议**：后端采用 SSE 或 Fetch Stream，接口契约 `/api/agent/run` + `/api/agent/stream`。
- **React 实时渲染**：后端流式输出 JSON Patch，React 前端实时渲染为结构化卡片（非纯文本 Markdown）。
- **断线重连与持久化**：
    - 前端保存 `last_sequence`，重连时携带以恢复事件流。
    - 后端引入任务级状态存储（task_id/thread_id），将 SnapshotStore 与 EventBus 替换为 Redis/DB 持久化。
- **进度可视化**：显示生成步骤状态（进行中/完成/失败），支持折叠/展开详情。
- **输入层优化**：目的地/天数/预算/偏好/出行人群的简化表单 + 模板引导。
- **稳定性保障**：
    - **熔断机制**：在 `call_tool` 层集成 `CircuitBreaker`，对搜索/爬虫等不稳定工具实施熔断降级。
    - **预算守卫**：引入 `BudgetManager` 与 `ConstraintChecker`，在调度前校验 Token/Cost/Time 预算。
- **地图联动**：生成的 POI 卡片点击可高亮地图点位，地图点位点击可滚动至对应卡片。

**验收标准：**
- 用户提交后，行程卡片逐个上屏，且地图点位同步出现。
- 支持网络断开后重连，并从断点处继续渲染流式内容。
- 生成过程中可随时取消，失败支持重试。
- 至少 1 个模板可直接填充表单完成生成。

### P0：可编辑能力（WYSIWYG）
**目标：** 补齐可视化编辑入口，**重构地图渲染层**以提升性能。

**功能清单：**
- **拖拽排序**：支持同一天内行程项的拖拽排序，地图路线实时更新。
- **定点修改**：支持点击行程卡片进行编辑（修改名称/时间/备注）或删除。
- **局部重生成**：按天重新规划（Replan Day），不影响其他天。
- **地图渲染重构**：
    - 后端：API 返回 GeoJSON 数据流（移除 Folium HTML 生成）。
    - 前端：使用 `React-Map-GL` + `Deck.gl`，支持视口剔除与聚合（Supercluster）。

**验收标准：**
- 拖拽行程项后，列表顺序与地图路线同步更新。
- 编辑/删除行程项后，数据状态同步更新。
- 缩放地图时 POI 自动聚合，无显著卡顿（支持 100+ POI）。

### P0：可解释性（决策辅助）
**目标：** 复用 v0.0.3 证据结构，增加结构化决策因子。

**功能清单：**
- **结构化标签**：在推荐理由中解析并展示评分（Rating）、类型（Tags）、建议游玩时长。
- **数据来源标注**：来源可点击跳转，增强可信度。
- **证据引用面板**：证据列表展示、筛选后重生成。

**验收标准：**
- 每个景点卡片显示推荐理由及结构化标签（如 ⭐4.5 | 🏛️博物馆 | ⏱️2h）。
- 证据面板展示并支持筛选后重生成。

### P1：知识库管理（RAG 增强）
**目标：** 持久化知识库并可复用，实现“私有数据增强”。

**功能清单：**
- **知识库管理**：创建/删除知识库，支持上传 PDF/Markdown/纯文本。
- **检索增强**：行程生成时可选择知识库，注入相关上下文（如“参考我的收藏列表”）。

**实现路径：** 沿用 Chroma，补齐持久化 collection 与文档解析接口。

**验收标准：**
- 上传一份 PDF 攻略，生成行程时能引用其中的景点或建议。

## 开发步骤建议

1.  **基础设施 (Infra)**：统一 SSE 协议、状态持久化 (Redis/DB)、LangGraph 迁移评估。
2.  **核心闭环 (Core Loop)**：React 流式组件化渲染、地图 GeoJSON 重构、输入表单优化。
3.  **交互增强 (Interaction)**：实现拖拽排序、定点修改、地图双向联动。
4.  **知识增强 (Knowledge)**：RAG 证据面板迁移、结构化标签解析、知识库管理后端。
5.  **验收 (Acceptance)**：端到端用例（输入->生成->拖拽->再生成）复现。

## 技术债务与后续规划

**本期暂缓（v0.0.5）：**
- **交易闭环**：暂不接入实时库存/价格/预订。
- **复杂预算**：暂不实现多币种/实时汇率/精细化预算管理。
- **多端同步**：暂不考虑移动端适配与多端同步。

### 实现逻辑说明
- **统一联动主键**：后端 GeoJSON 点位写入 `poi_id = day-index`，前端行程卡片使用同样的 `day-index` 作为卡片标识，确保列表与地图可互相定位。
- **卡片 → 地图**：卡片点击时写入 `selectedPoiId`，地图图层根据该值切换点位样式与半径实现高亮。
- **地图 → 卡片**：地图点位点击时读取 `poi_id`，写入 `selectedPoiId`，由列表组件 `scrollIntoView` 滚动到对应卡片并高亮。
- **滚动与高亮**：列表维护 `poiId -> DOM` 引用表，`selectedPoiId` 更新后触发平滑滚动与高亮状态。

核心逻辑片段（省略细节）：
```text
cardId = `${dayKey}-${index}`
onCardClick: setSelectedPoiId(cardId) ...
onMapClick: setSelectedPoiId(feature.properties.poi_id) ...
selectedPoiId -> cardRefs[poiId].scrollIntoView(...) ...
selectedPoiId -> ScatterplotLayer getFillColor/getRadius ...
```
1. **工具层稳定性保障**
   - 在 `ToolRegistry.call` 内部新增熔断与时间预算校验，若工具处于熔断期则直接返回 `TOOL_CIRCUIT_OPEN`。
   - 记录工具调用耗时，超过 `TOOL_CALL_MAX_DURATION_SECONDS` 时返回 `BUDGET_EXCEEDED` 并计为失败，触发熔断计数。
   - 相关配置集中在 `Config`：`TOOL_CIRCUIT_FAILURE_THRESHOLD` / `TOOL_CIRCUIT_COOLDOWN_SECONDS` / `TOOL_CALL_MAX_DURATION_SECONDS`。
2. **Agent 全局预算守卫**
   - 在 `AgentExecutor.run_agent_loop` 主循环开头计算累计耗时并校验 `BudgetManager`。
   - 超出 `time_budget_seconds` 时发出 `error` 事件并终止执行，`stop_reason` 标记为 `budget_exceeded`。
   - 预算配置优先读取 `agent_config.time_budget_seconds`，缺省时使用 `AGENT_TIME_BUDGET_SECONDS`。
3. **统一流式协议补丁事件**
   - 当工具/行程/地图/摘要写入 `SharedContext` 时，统一发出 `context_patch` 事件。
   - 事件 payload 中包含 `patch`（JSON Patch 操作列表）以及 `task_id/key/value`，供前端增量渲染。
4. **前端增量渲染与输入优化**
   - 前端接收 `context_patch` 后解析 JSON Patch，针对 `t4.draft_trip` 触发行程更新、`t5.map_payload` 刷新地图 HTML。
   - 聊天输入支持 Enter 发送、Shift+Enter 换行，降低输入成本。
5. **行程流式断线重连补齐**
   - 后端行程流式接口引入 `message_id`/`last_sequence`，缓存事件并支持 `Last-Event-ID` 续传，断线后可从序号恢复。
   - 前端流式请求在重试时携带 `message_id` 与 `last_sequence`，自动续接并避免重复渲染。

### 实现逻辑说明
- **结构化标签与推荐理由**：在后端行程数据结构中补充 `rating/tags/recommend_reason/sources`，并在行程生成提示词中要求模型输出评分、类型与推荐理由，保证每个景点可直接渲染结构化标签。
- **景点卡片展示**：前端行程卡片从 `rating/tags/duration` 拼接结构化标签行（⭐评分/🏷️类型/⏱️时长），同时展示推荐理由与来源链接，点击可跳转原始来源。

## P0：Agent 编排架构升级（LangGraph）
**现状：** 项目已引入 `langgraph` 依赖并在调研文档中验证了 PoC，但核心调度仍基于自研 `Scheduler` (src/agent/scheduler.py) 与 `PlannerAgent`。

**目标：** 将生产环境的 `agent_loop.py` 全面迁移至 **LangGraph 标准实现**，移除自研调度器，统一编排与状态管理。

**升级路径：**
1.  **State 定义迁移**：将 `Plan/Task/SharedContext` (src/agent/plan_models.py) 映射为 LangGraph 的 `TypedDict` State。
2.  **调度器替换**：废弃 `src/agent/scheduler.py`，使用 `StateGraph` 定义节点 (Planner/Executor) 与边 (Edges)。
3.  **持久化升级**：使用 `langgraph.checkpoint` 替换原有的 `SnapshotStore`，实现开箱即用的断点恢复与历史回放。
4.  **工具层复用**：直接复用 `LlmManager` 中已封装的 LangChain Tools (`@tool`)，无缝接入 Graph 节点。

**功能清单：**
- **LangGraph 迁移**：重构 `PlannerAgent` 为 Graph Node，构建 `StateGraph` 替代 `agent_loop`。
- **子图拆分**：将规划（Planner）、执行（Executor）、反思（Reflector）拆分为独立的 SubGraph，支持更灵活的编排。
- **Human-in-the-loop**：利用 LangGraph 的 `interrupt` 机制，在关键决策节点（如预算超支、行程冲突）引入人工确认。

**验收标准：**
- 成功运行完整的行程生成流程，且状态转换在 LangSmith 或本地日志中可观测。
- 支持在任意节点暂停并恢复执行（利用 Checkpoint）。
- 实现至少一个 Human-in-the-loop 场景（如：工具调用失败时请求用户干预）。

### 实现逻辑说明
- **State 迁移**：将 `TripState/Plan/SharedContext` 序列化为 LangGraph `TypedDict`，在执行前/后做双向映射，保证 checkpoint 可持久化。
- **Graph 拓扑**：Planner → Scheduler → Executor → Reflector → Scheduler 循环，Planner/Executor/Reflector 以 SubGraph 形式挂载，便于后续拆分与复用。
- **调度替换**：Scheduler Node 直接计算就绪任务与并发窗口，替代原 `Scheduler` 类与批次循环逻辑。
- **Checkpoint 恢复**：统一使用 `langgraph.checkpoint` 保存线程状态，通过 thread_id 复用状态并支持 resume。
- **Human-in-the-loop**：工具失败触发 `interrupt`，暂停执行并抛出 `__interrupt__` 供前端决策，resume 时支持 skip/override/retry。
