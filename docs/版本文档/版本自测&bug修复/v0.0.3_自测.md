# v0.0.3 自测清单与用例

目标：基于 v0.0.3 版本开发内容，覆盖端到端链路、工具协议、流式输出、RAG 证据、Agent 编排与性能稳定性等关键能力。

## 测试前置

- 启动方式与运行入口以当前项目默认方式为准
- 准备可用的联网环境与必要的模型配置（本地/云端均可）：先使用公司大模型，验证token可视化等功能正常后再使用线上模型进行测试（参数比较大的模型，要求速度）
- 确保可访问城市：成都、东京、上海（便于地理编码与 POI/天气校验）


## 测试内容顺序

1. 工具调用成功与失败路径 ✅
2. 流式输出与 UI 渲染稳定性 ✅
3. 行程生成与修改核心路径 ✅
4. Agent 编排、暂停与恢复  + RAG 证据结构与前端可视化交互 
5. 地图渲染与 POI 展示
7. 缓存、并发与错误规范


## 主流程


### ✅1. 工具协议与最小工具集

#### ✅1.1 工具注册表与 Schema

- 步骤
  - 启动应用
  - 触发工具列表读取（运行时或日志中能看到工具列表 JSON）
- 预期
  - 【控制台】工具列表包含 weather.get_daily / geo.geocode / poi.search
  - 【控制台】Schema 字段包含 name/description/params/returns/errors

#### ✅1.2 工具直接调用（本地调用入口）

- 输入
  - weather.get_daily：城市=成都，天数=3
  - geo.geocode：地址=成都市天府广场
  - poi.search：查询=成都 宽窄巷子
- 预期
  - 【控制台】返回结构化结果且 success 为 true
  - 【控制台】错误时返回统一错误结构，不抛出未捕获异常

#### ✅1.3 LLM 工具路由（非 FunctionCall）

- 输入
  - “帮我查成都最近天气”
  - “给我推荐上海外滩附近景点”
  - “天安门经纬度是多少”
- 预期
  - 【控制台】needs_tool 为 true
  - 【控制台】tool_name 与 params 匹配（天气/POI/地理编码）
  - 【界面】工具结果被注入上下文或直接作为回复输出

#### ✅1.4 FunctionCall 路由（云端模型）

- 前置
  - 切换到支持 FunctionCall 的云端模型
- 输入
  - “查询东京接下来 5 天的天气”
- 预期
  - 【控制台】走 FunctionCall 绑定工具的路径
  - 【控制台】tool_calls 中解析到正确工具与参数
  - 【控制台】结果返回结构与非 FunctionCall 保持一致

### ✅2. 行程生成与修改入口

#### ✅2.1 生成行程（工具预调用注入）

- 输入
  - 目的地=成都，天数=3，偏好=历史与美食
- 预期
  - 【界面】生成结构化行程 JSON
  - 【控制台】如果触发工具预调用，能看到“工具结果”注入上下文

#### ✅2.2 对话修改（通用意图）

- 输入
  - “把第二天行程改得更轻松，加入一个博物馆”
- 预期
  - 【界面】识别为修改意图并返回更新后的行程
  - 【控制台】无未解析 JSON 或崩溃

#### ✅2.3 工具优先的对话请求

- 输入
  - “北京明天会下雨吗”
- 预期
  - 【界面】直接返回工具结果，不走行程生成

### ✅3. 流式输出与 UI 渲染

#### ✅3.1 流式事件协议

- 操作
  - 触发一次对话流式响应
- 预期
  - 【控制台】事件顺序为 start → delta* → end
  - 【控制台】sequence 单调递增
  - 【控制台】end 事件能汇总完整文本

#### ✅3.2 UI 渲染节流与稳定性

- 操作
  - 发送长文本问题（如“东京三日游攻略有哪些值得参考的行程安排？”）
- 预期
  - 【界面】UI 渲染不卡顿或抖动明显降低
  - 【界面】未出现重复段落或文本错乱

### ✅4. 地图渲染与 POI

#### ✅4.1 地理编码回退

- 输入
  - 故意输入难以解析的地址或景点
- 预期
  - 【界面】回退到城市中心坐标
  - 【界面】地图仍可渲染

#### ✅4.2 POI 按天分层与批量渲染

- 操作
  - 生成 3 天游程并打开地图
- 预期
  - 【界面】按天分组渲染图层
  - 【界面】多点位批量打点不出现渲染卡顿或遗漏


## Agent模式

### 1. ✅RAG 质量与 Evidence Budget

#### 1.1 ✅Summary/Body 结构与预算

- 输入
  - “东京三日游攻略有哪些值得参考的行程安排？”
- 预期
  - 【界面】返回 evidence.summary 与 evidence.body
  - 【界面】summary/body 各自有 items 与 used_chars/budget_chars
  - 【界面】budget 中包含 summary_max_chars 与 body_max_chars

#### 1.2 ✅证据去重与截断

- 操作
  - 使用覆盖面较大的问题触发多条来源
- 预期
  - 【界面】summary 去重后不出现高度重复条目
  - 【界面】单条 summary 与 body 不超过单条最大长度限制

#### 1.3 ✅超长段落自动摘要

- 操作
  - 选择内容较长的检索主题（如“日本铁路通票全指南”）
- 预期
  - 【界面】body 中超长段落被压缩，且不超过证据预算

#### 1.4 ✅前端证据面板交互

- 操作
  - 打开证据面板
  - 勾选、置顶、筛选、编辑文本
  - 点击“用已选证据生成回答”
- 预期
  - 【界面】交互状态可保持
  - 【界面】生成回答基于当前选中证据

### ✅2. Agent 计划与执行循环

#### ✅2.1 计划生成与预览

- 操作
  - 进入 Agent 调试面板
  - 点击“生成计划”
- 预期
  - 【界面】展示中文任务排序预览（如：1 查询天气 → 2 查询景点 → 3 查询地理编码 → 4 生成行程 → 5 渲染地图 → 6 输出摘要）

#### ✅2.2 计划确认与执行

- 操作
  - 点击“确认执行”
- 预期
  - 【界面】执行批次任务并更新任务状态
  - 【界面】输出 final_payload（draft_trip/map_payload/summary）

#### ✅2.3 事件总线与快照

- 操作
  - 观察事件面板与快照面板
- 预期
  - 【界面】事件包含 batch_start/replan/error/loop_end
  - 【界面】批次结束生成快照

#### ✅2.4 计划重规划（Re-plan）

- 操作
  - 触发工具返回空结果或失败
- 预期
  - 【界面】触发 replan 事件
  - 【界面】重规划后继续执行



## 性能与稳定性

### ✅LLM 调用合并

- 操作
  - 触发一次行程生成与一次行程修改
- 预期
  - 【控制台】识别/抽取调用合并为一次
  - 【控制台】生成/修改保持一次调用

### 缓存与 TTL 复用

- 操作
  - 重复查询同一城市天气与同一 POI
- 预期
  - 【控制台】命中缓存后响应时间下降

### ✅并发限制与超时熔断

- 操作
  - 并行触发多次检索
- 预期
  - 【控制台】达到并发上限后触发回退策略
  - 【控制台】超时有统一错误输出，不影响整体服务稳定性
