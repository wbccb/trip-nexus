# v0.0.4 自测清单与用例

目标：覆盖 v0.0.4「生成体验 + 可编辑 + 可解释 + LangGraph 编排 + 知识库增强」的核心闭环，确保 React 前端与 API 后端在真实链路下稳定可用。

## 测试前置

- 启动前后端服务（React + API），并确保可访问地图与联网检索能力
- 准备至少 3 组测试城市：东京、上海、成都（覆盖天气、POI、地理编码差异）
- 准备 1 份可上传文档（PDF/Markdown/TXT 任一），用于知识库增强验证
- 使用一个支持 FunctionCall 的模型配置（用于工具链路与 Agent 执行验证）
- 打开浏览器开发者工具（Network + Console），便于观察 SSE 事件与接口返回

## 测试内容顺序

1. 生成体验与流式协议（SSE / JSON Patch / 断线重连）
2. 可编辑能力（拖拽 / 编辑删除 / 局部重生成 / 地图联动）
3. 可解释性（结构化标签 / 来源跳转 / 证据筛选重生成）
4. Agent 编排（LangGraph 状态流转 / Checkpoint 恢复 / HITL）
5. 知识库管理（创建删除上传 + 行程注入）
6. 稳定性守卫（工具熔断 + 时间预算）
7. 回归链路（输入→生成→编辑→再生成）

## 主流程

### 1. 生成体验与流式协议升级【Agent状态】

#### 1.1 `/api/agent/run` + `/api/agent/stream` 协议连通

- 操作
  - 提交一次完整行程请求（目的地=东京，天数=3，偏好=美食+赏樱）
  - 观察是否先创建运行任务，再进入流式通道
- 预期
  - 【Network】能看到运行接口与流式接口均返回成功
  - 【界面】结构化卡片按生成过程逐步上屏，不是一次性整块渲染

#### 1.2 `context_patch` 增量渲染

- 操作
  - 触发一次带地图与行程的生成流程
  - 观察流式事件体是否包含 patch 操作
- 预期
  - 【Network/Console】出现 `context_patch` 事件，且 `patch` 为 JSON Patch 数组
  - 【界面】行程列表与地图区域可随事件持续更新

#### 1.3 断线重连与续传（`message_id` / `last_sequence`）

- 操作
  - 生成中手动断网 3~5 秒后恢复
  - 或关闭当前流式请求后，以相同任务参数触发重连
- 预期
  - 【Network】重连请求携带 `message_id` 与 `last_sequence`（或 `Last-Event-ID`）
  - 【界面】从断点继续，不重复刷已渲染内容

#### 1.4 生成取消与失败重试

- 操作
  - 生成过程中点击取消
  - 再点击重试同一请求
- 预期
  - 【界面】取消后停止新增流式内容
  - 【界面】重试后可重新进入生成流程并产出结果

### 2. 可编辑能力（WYSIWYG）【主流程】

#### 2.1 同日行程拖拽排序

- 操作
  - 在同一天内拖拽 2~3 个行程项调整顺序
- 预期
  - 【界面】列表顺序立即更新
  - 【界面】地图路线顺序同步变化

#### 2.2 定点修改与删除

- 操作
  - 修改某一景点名称/时间/备注
  - 删除某一行程项
- 预期
  - 【界面】卡片内容即时更新
  - 【界面】被删除项从列表与地图点位同时移除

#### 2.3 按天局部重生成（Replan Day）

- 操作
  - 仅对第 2 天触发重生成
- 预期
  - 【界面】第 2 天内容发生替换，其他天保持不变
  - 【界面】地图仅对应更新受影响日期的点位/路线

#### 2.4 地图双向联动（卡片↔点位）

- 操作
  - 点击某个行程卡片
  - 再点击地图上的对应 POI 点
- 预期
  - 【界面】卡片点击后地图点位高亮
  - 【界面】点位点击后列表自动滚动并高亮对应卡片

#### 2.5 地图缩放聚合性能

- 操作
  - 构造 100+ POI 的行程数据并连续缩放/拖拽地图
- 预期
  - 【界面】POI 自动聚合，无明显卡顿
  - 【界面】放大后聚合点可平滑展开为单点

### 3. 可解释性（决策辅助）【主流程/RAG流程】

#### 3.1 结构化标签展示

- 操作
  - 生成行程并查看景点卡片
- 预期
  - 【界面】每个景点可见评分/类型/建议时长（如 ⭐4.5 | 🏛️博物馆 | ⏱️2h）
  - 【界面】同时展示推荐理由文本

#### 3.2 数据来源跳转

- 操作
  - 点击景点卡片中的来源链接
- 预期
  - 【界面】可跳转到对应来源页面
  - 【界面】来源标注与当前推荐内容语义一致

#### 3.3 证据面板筛选后重生成

- 操作
  - 打开证据面板，使用关键词/置信度筛选并勾选证据
  - 点击“基于已选证据重生成”
- 预期
  - 【界面】重生成内容明显受所选证据影响
  - 【界面】未选证据的信息不应大量出现在结果中

### 4. Agent 编排架构（LangGraph）【Agent状态】

#### 4.1 状态流转可观测性

- 操作
  - 执行一次完整 Agent 流程并观察日志/事件面板
- 预期
  - 【日志/界面】可观察 Planner → Scheduler → Executor → Reflector 的节点流转
  - 【日志/界面】存在任务级状态变化记录（进行中/完成/失败）

#### 4.2 Checkpoint 暂停与恢复

- 操作
  - 在执行中断开会话或主动暂停
  - 使用同一 `thread_id` 恢复
- 预期
  - 【日志/界面】恢复后从中断点继续，而非全量重跑
  - 【界面】最终结果与连续执行版本一致

#### 4.3 Human-in-the-loop 中断处理

- 操作
  - 人为制造工具失败（如无效参数/超时）触发中断
  - 分别执行 skip / override / retry 三类决策
- 预期
  - 【日志/界面】出现 `__interrupt__` 或等价中断信号
  - 【界面】三种决策均可恢复执行并产生可解释结果

### 5. 知识库管理（P1）【RAG流程】

#### 5.1 知识库创建、删除、列表刷新

- 操作
  - 新建知识库 -> 刷新列表 -> 删除知识库
- 预期
  - 【界面】列表状态与操作一致
  - 【接口】增删改返回成功，异常时有清晰错误提示

#### 5.2 文档上传与入库

- 操作
  - 向知识库上传 1 份 PDF 或 Markdown
- 预期
  - 【接口】返回上传成功与入库 chunk 数量
  - 【界面】上传后该知识库可被选择用于行程生成

#### 5.3 行程生成注入知识库上下文

- 操作
  - 选择知识库并输入“参考我上传的攻略安排 3 天行程”
- 预期
  - 【界面】结果中出现上传文档中的景点/建议
  - 【界面】推荐理由或证据可追溯到私有知识内容

### 6. 稳定性保障【Agent状态】

#### 6.1 工具熔断机制（CircuitBreaker）

- 操作
  - 连续触发某工具失败（如多次请求不可达服务）
- 预期
  - 【日志】达到阈值后进入熔断期，返回 `TOOL_CIRCUIT_OPEN`（或等价状态）
  - 【日志】冷却期后可恢复尝试调用

#### 6.2 时间预算守卫（BudgetManager / ConstraintChecker）

- 操作
  - 设置较小时间预算并触发较长流程
- 预期
  - 【日志/界面】超预算后终止执行并输出 `budget_exceeded`（或等价原因）
  - 【界面】有可理解的失败提示，不出现无响应卡死

## 端到端回归清单（必须全绿）

- 输入表单提交后可稳定进入流式生成
- 行程卡片与地图可双向联动
- 拖拽/编辑/删除/局部重生成均可用
- 推荐理由含结构化标签与来源链接
- 证据筛选后可驱动重生成
- Agent 可暂停恢复，且中断可人工决策
- 知识库上传后可在行程中被引用
- 断线重连、熔断、预算超限均有稳定降级
