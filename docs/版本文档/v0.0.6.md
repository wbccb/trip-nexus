# v0.0.6

## 一、版本定位

v0.0.6 的核心目标：在延续 v0.0.5「单主流程」稳定性的前提下，完成从“行程生成工具”到“中立旅行决策与共创平台”的产品能力升级。

本版本不与 OTA 在交易履约上正面竞争，聚焦三类差异化价值：
1. 深度信息整合：融合公网长尾内容与用户私有知识。
2. 人机协同创作：支持可编辑、可回滚、可解释的行程共创过程。
3. 非标场景规划：优先解决复杂约束场景而非标准化热门线路。

## 二、版本目标（对应护城河方向，含社交接入 L0-L3 全链路落地）

1. **知识护城河目标**：将“知识库”从技术能力升级为 C 端高感知功能，形成用户私有旅行资产沉淀。
2. **体验护城河目标**：将 HITL + Agent Checkpoint 能力前台化，建立“可控修改、局部重排、结果可解释”的交互闭环。
3. **场景护城河目标**：补齐非标规划所需的“约束输入 + 冲突检测 + 替代方案”能力。
4. **生态护城河目标**：建立行程导出与分发能力，把 TripNexus 定位为决策上游入口。

## 三、范围定义

### 3.1 本版本纳入范围

1. 旅行灵感收纳箱（Knowledge Base 产品化）
   - 支持更明确的知识来源管理与使用状态感知。
   - 支持在生成行程前设置“本次优先参考的知识资产”。
   - 社交 URL 分层接入能力在 v0.0.6 落地 L0-L3 全链路（含 L2 有限平台适配、L3 浏览器渲染兜底）。
2. 行程约束显式化（Constraints UI + Prompt 注入）
   - 增加预算、体能强度、节奏偏好、家庭友好等约束参数。
   - 约束参数进入主流程并参与生成/修改。
3. 冲突检测与解释（Conflict Check）
   - 针对时间冲突、路程过长、节奏过密给出 warning。
   - 提供 Plan A / Plan B 两套替代建议。
4. 局部重排增强（Replan by Scope）
   - 支持“锁定不改动天数 + 指定单天/半天重排”。
   - 保留原有 Agent 升级与恢复能力。
5. 分享与克隆（Fork & Tweak）
   - 支持结构化行程生成分享链接。
   - 支持基于分享行程继续微调。

### 3.2 本版本不纳入范围

1. 不建设机票/酒店交易闭环，不接入支付与订单系统。
2. 不做全量社交社区，仅落地“分享与克隆”的最小闭环。
3. 不新增重型推荐系统，仅在现有 LLM + RAG + 工具体系上扩展规则与流程。

## 四、需求规划（按能力域）

### 4.1 旅行灵感收纳箱（P0）

#### 4.1.1 用户价值
1. 用户可把碎片化攻略、游记、PDF 变成可复用的个人知识资产。
2. 行程生成时可被“定向引用”，避免 AI 输出泛化模板行程。

#### 4.1.2 功能需求
1. 知识库管理增强
   - 显示知识库来源类型（PDF/Markdown/URL/TXT）。
   - 显示知识条目数量与最后更新时间。
2. 生成链路接入增强
   - `knowledge_base_id` 保持必传可选。
   - 新增 `knowledge_query` 默认值策略（当用户未填写时，自动基于目标地 + 偏好构建查询）。
3. 证据可见性
   - 前端可查看本次使用的 summary/body evidence 摘要。
   - 支持“仅使用私有知识 / 私有+公网融合”开关。

#### 4.1.3 社交数据接入策略

> 详细技术方案见 `docs/技术难点/社交URL内容获取方案.md`

1. 核心策略
   - 按”内容获取方式分层”而非”按平台逐一攻克抓取”。
   - 对开放网页：自动抓取做到稳定。对高风险社交平台：用户辅助导入做到顺滑。
   - 不做反爬对抗能力，不绕过平台访问限制。

2. 平台分级（v0.0.6 落地）
   - **低风险**（博客、媒体、攻略站）：`requests + bs4` 自动提取，高成功率。
   - **中风险**（知乎公开问答、B站）：自动提取 + 质量门禁，失败时引导手动导入。
   - **高风险**（小红书、微博）：用户辅助导入优先，自动抓取仅 best effort。
   - 平台识别范围：`xiaohongshu`、`weibo`、`zhihu`、`bilibili`、`unknown`。

3. 分层获取架构（v0.0.6 落地 L0 + L1 + L2 + L3）
   - **L0 URL 预处理层**：URL 规范化、去追踪参数、短链解跳（`xhslink.com`/`b23.tv`/`t.cn`）、平台识别、风险等级识别。
   - **L1 开放网页自动提取层**：复用现有 `requests + BeautifulSoup`，补齐元信息提取（`og:title`/`og:description`）和质量门禁。
   - **L2 有限平台适配层**（v0.0.6 落地）：仅做最小化元信息 + 公开首屏正文提取，不承诺评论区/多页/登录后内容。
   - **L3 浏览器渲染兜底层**（v0.0.6 落地）：Playwright 仅用于公开页 CSR 补救，不负责绕过登录/风控。

4. 入库前质量门禁（v0.0.6 落地）
   - 新增 `validate_content_quality(content_text, metadata)` 函数。
   - 检查项：最小字符数（`>= 80`）、有效文本密度（`>= 0.15`）、中文内容比例（`>= 0.3`）、重复段比例（`< 0.4`）、噪声模板命中。
   - `quality_score` 0-100，入库阈值 `>= 40`。
   - 去重判定：同 `knowledge_base_id` 下相同 `resolved_url` 已有高相似度条目则拒绝入库。

5. 新增错误码（v0.0.6 落地）
   - `AUTO_PARSE_EMPTY`：有效文本 < 80 字符
   - `AUTO_PARSE_LOW_QUALITY`：quality_score < 40
   - `AUTO_PARSE_DUPLICATED`：重复内容
   - `AUTO_PARSE_BLOCKED`：命中”下载 App”等关键词
   - `AUTO_PARSE_LOGIN_REQUIRED`：命中登录提示关键词
   - `AUTO_PARSE_RISK_VERIFICATION`：命中验证码/人机验证关键词
   - `AUTO_PARSE_PAYWALLED`：命中会员/付费关键词
   - `URL_RESOLVE_LOOP`/`URL_RESOLVE_TIMEOUT`：短链解跳异常

6. 前端交互增强（v0.0.6 落地）
   - URL 输入后、导入前：根据 `source_risk_level` 展示前置引导文案（低风险默认自动、高风险默认手动）。
   - 导入失败后：按 `source_platform` + `ingest_error_code` 展示平台级引导文案，引导用户切换手动导入。
   - 来源列表增加：平台标签（带图标）、风险等级颜色标识、错误码 hover 说明。

7. P1 范围（下版本）
   - 登录态授权导入（仅在用户授权和平台规则允许时启用）。
   - 图文 OCR、短视频字幕抽取等多模态增强。

8. P2 范围（后续）
   - 浏览器插件/书签脚本授权导入。
   - 按 ROI 建设平台专属 connector。

9. 合规边界
   - 不绕过平台访问限制，不破解登录态，不提供反爬对抗策略。
   - 支持数据可追溯、可删除、可过期。


### 4.2 行程约束显式化（P0）

#### 4.2.1 用户价值
1. 用户可直接表达“预算/体力/家庭成员限制”等硬条件。
2. 降低反复口头修正成本，提升首版行程可用度。

#### 4.2.2 功能需求
1. 约束输入面板
   - 预算档位：经济/均衡/舒适。
   - 体能强度：休闲/标准/特种兵。
   - 节奏偏好：文化探索/打卡效率/亲子友好。
   - 特殊约束：步行上限、午休需求、无障碍需求。
2. 约束协议统一
   - 前端将约束归一为结构化对象。
   - 后端在主流程内注入 LLM prompt 与重排行为。
3. 结果可追踪
   - 输出中标记关键约束是否满足（如“已控制单日步行强度”）。
   - 前端展示约束满足状态，后端在主流程内注入 LLM prompt 与重排行为。

#### 4.2.3 对应现有模块
1. 前端：`web/src/components/TripTab.jsx`、`web/src/hooks/useTrip.js`
2. 后端：`src/llm/llm_manager.py`（build_prompt / change_trip）

### 4.3 冲突检测与解释（P0）

#### 4.3.1 用户价值
1. 在不合理行程出现时给出明确原因，而不是直接失败或静默改写。
2. 用户可在“坚持原方案”和“接受替代方案”之间做决策。

#### 4.3.2 功能需求
1. 冲突检测规则
   - 距离与时间冲突（半天跨城、连续超长交通）。
   - 节奏冲突（单日 POI 过密、无休息窗口）。
2. 解释与替代输出
   - 输出冲突原因文本。
   - 输出 Plan A（保守可执行）/Plan B（满足偏好但风险更高）。
3. 流式事件扩展
   - 在 `step` 事件中增加 `warning/conflict` 类型，前端高亮展示。

#### 4.3.3 对应现有模块
1. 后端：`src/api/app.py`（流式事件输出）、`src/llm/llm_manager.py`
2. 前端：`web/src/api/flowApi.js`、`web/src/components/TripTab.jsx`

### 4.4 局部重排与可控共创（P1）

#### 4.4.1 用户价值
1. 用户可只改动某一天或某半天，减少“全局重算导致满意部分被破坏”。
2. 强化用户掌控感，提升多轮编辑体验。

#### 4.4.2 功能需求
1. 锁定机制
   - 支持锁定 day/block，不参与重排。
2. 局部重排
   - 支持“仅重排第 N 天”或“第 N 天下午”。
3. Agent 升级条件联动
   - 当局部重排触发跨天依赖时，自动升级 Agent 并返回触发原因。

#### 4.4.3 对应现有模块
1. 后端：`src/agent/agent_loop.py`、`src/api/app.py`
2. 前端：`web/src/components/TripTab.jsx`、`web/src/components/TripMap.jsx`

### 4.5 分享与克隆（P1）

#### 4.5.1 用户价值
1. 用户可快速把结构化成果外发，形成自然传播。
2. 新用户可在现有方案上二次编辑，降低冷启动门槛。

#### 4.5.2 功能需求
1. 分享
   - 生成可访问链接（包含行程结构与必要摘要）。
2. 克隆
   - 新会话可加载分享方案并继续编辑。
3. 权限与安全
   - 默认匿名分享，不包含用户隐私上下文。

#### 4.5.3 对应现有模块
1. 前端：`web/src/App.jsx`、`web/src/hooks/useTrip.js`
2. 后端：`src/api/app.py`（新增分享/克隆接口）

## 五、非功能需求

1. 性能
   - 常规生成链路时延相对 v0.0.5 增量不超过 20%。
2. 稳定性
   - 冲突检测失败不阻断主流程，自动降级为普通生成并记录 warning。
3. 可观测性
   - 新增指标：`constraint_used`、`conflict_detected`、`plan_alternative_generated`、`share_created`、`fork_started`。
   - 新增社交导入指标：`social_ingest_total`、`social_ingest_success_rate`、`social_ingest_fallback_rate`、`social_ingest_by_platform`（按平台统计）、`social_ingest_by_risk_level`（按风险等级统计）、`quality_gate_reject_rate`（质量门禁拒绝率）。
4. 可维护性
   - 新增字段优先复用现有 `/api/flow/stream` 协议，不新增并列主链路。
5. 合规性
   - 社交链接接入全链路保留来源 metadata 与删除能力，满足最小合规要求。

## 六、验收标准

### 6.1 功能验收

1. 旅行灵感收纳箱可完成创建、上传、选择并参与行程生成。
2. 社交链接导入可完成”解析成功入库”与”解析失败降级导入”两条路径。
   - URL 预处理（短链解跳、平台识别、风险分级）正常工作。
   - 质量门禁可拦截低质量/噪声页面并返回准确错误码。
   - 前端可根据平台和风险等级展示差异化引导文案。
3. 约束参数可被稳定传递并影响行程结果。
4. 冲突场景可返回可解释 warning 与替代方案。
5. 局部重排支持锁定与指定范围改动。
6. 分享链接可打开并支持克隆后二次编辑。

### 6.2 体验验收

1. 用户在 3 次以内编辑中可完成“初版->可执行版”行程收敛。
2. 冲突提示可读且可操作，不出现“只报错不给建议”。
3. 局部重排后，未锁定部分保持最小变更原则。

### 6.3 技术验收

1. 主流程事件协议兼容现有前端消费逻辑。
2. 新增功能不破坏 v0.0.5 的 pause/resume/retry 闭环。
3. 核心接口具备最小回归测试样例（知识库注入、约束注入、冲突警告、局部重排）。

## 七、优先级与排期建议

### P0（本版本必须落地）
1. 旅行灵感收纳箱产品化（可见性 + 使用策略）。
2. 约束输入面板与后端注入链路。
3. 冲突检测与解释输出（含流式 warning 事件）。
4. 社交内容接入网关 P0（通用 URL 解析 + 失败降级 + 来源标注）。

### P1（本版本应做）
1. 局部重排锁定机制。
2. 分享与克隆最小闭环。
3. 社交数据授权导入与多模态增强（OCR/字幕抽取）。

### P2（可延后）
1. 多平台外部导出（Notion/日历）标准化。
2. 逆向比价与分销链接能力。

## 八、版本成功判定（Go / No-Go）

满足以下条件可判定 v0.0.6 达标：
1. P0 功能全部上线并通过自测。
2. 常规链路稳定性不低于 v0.0.5。
3. 至少一个非标场景（如亲子/自驾/高强度）形成可复用演示样例。
4. 用户可感知“我的知识 + 我的约束 + 我的可控修改”三项核心差异化体验。




## 九、开发实施记录

### 9.1 旅行灵感收纳箱（P0）

#### 9.1.1 任务规划（前端 / 后端 / API / 数据结构 / 验收用例）
1. 前端任务规划（P0）
   - 在 `KnowledgeTab.jsx` 提供社交链接导入入口（URL 输入框 + 导入按钮）。
   - 增加导入状态机：解析中、成功、失败、降级建议（手动粘贴/OCR）。
   - 在来源列表展示 `source_type/source_platform/source_url/ingest_status`，并增强可读性（平台标签、风险标识、错误码提示）。
   - 支持失败后一键切换到手动导入模式（文本粘贴 + OCR 文本）。
   - URL 输入后调用预处理接口，按 `source_risk_level` 展示前置引导文案。
   - 自动导入失败后按 `source_platform + ingest_error_code` 展示平台级引导文案。
   - P1 延伸：增加失败来源展示、失败后补全文本重试入口、命中来源与来源总览分区展示、OCR/字幕导入入口。
2. 后端任务规划（P0）
   - 在 `app.py` 落地社交导入编排：参数校验 -> L0 URL 预处理 -> URL 抓取 -> 正文抽取 -> 质量门禁 -> 标准化 -> 入库。
   - 新增 `src/rag/network/url_preprocessor.py`：URL 规范化、去追踪参数、短链解跳、平台识别、风险等级映射。
   - 新增 `src/rag/network/content_validator.py`：`validate_content_quality()` 与质量评分（0-100，阈值 >= 40）。
   - 平台识别补齐 `zhihu.com` / `zhuanlan.zhihu.com`。
   - 引入 L2 有限平台适配层与 L3 浏览器渲染兜底层。
   - 在入库 metadata 中补齐 `normalized_url/resolved_url/source_risk_level/extractor_layer/quality_score` 等字段。
   - 增加来源删除、来源追踪、过期清理标记等合规能力。
   - P1 延伸：失败来源持久化、失败来源原位重试、`source_evidence` 精确命中反查、OCR/字幕文本标准入库编排。
3. API 任务规划（P0）
   - `POST /api/knowledge/bases/{knowledge_base_id}/ingest/url`：支持 `auto/manual` 导入与 fallback 返回。
   - `POST /api/knowledge/preprocess/url`：前端在输入 URL 后预获取平台与风险等级。
   - `GET /api/knowledge/bases/{knowledge_base_id}/sources`：返回来源列表与导入状态统计。
   - `DELETE /api/knowledge/bases/{knowledge_base_id}/sources/{source_id}`：按来源删除分块用于撤回。
   - P1 延伸：`sources` 返回失败来源与更完整错误信息；新增或扩展来源重试接口；`knowledge/search` 与 `flow/stream` 仅返回本次实际命中来源。
4. 数据结构任务规划（P0）
   - metadata 标准字段包含 `source_id/source_type/source_platform/source_url/ingest_mode/ingest_status/ingest_error_code/ingested_at/expires_at`。
   - metadata 扩展字段包含 `normalized_url/resolved_url/source_risk_level/extractor_layer/quality_score`。
   - RAG 检索结果透传 `source_type/source_platform/source_url/ingest_status` 用于前端证据展示。
   - P1 延伸：补齐 `failure_reason/last_retry_at/retry_count/hit_chunk_ids/hit_count` 等字段。
5. 验收用例规划（P0）
   - 解析成功：公开 URL 导入成功，`ingest_status=parsed`，可被检索命中。
   - 解析失败降级：自动解析失败后，手动文本补全成功，`ingest_status=fallback`。
   - metadata 完整性：来源字段可查询且前端列表可见。
   - 删除与撤回：删除 `source_id` 后对应分块不再被召回。
   - 合规边界：受限链接返回明确错误码，不触发绕过策略。
   - 平台分级引导、质量门禁、短链解跳、去重判定、L2/L3 提取路径均有回归用例。

- 精确命中验证：执行知识检索或主流程后，调试区 `source_evidence` 仅展示本次实际命中的来源，不再展示无关来源样本。

11. 当前已知边界（按现状判定）
- `preprocess/url` 现在会做一次无副作用的“试解析”，但不会做去重判定、失败来源落库或真正入库；它的作用是预判，不是替代 `ingest/url`。
- 预处理阶段拿到的 `quality_score`、`extractor_layer` 与失败码属于 best effort 结果；若目标页面在短时间内发生内容变化、风控升级或重定向变化，实际导入结果仍可能不同。
- L2/L3 的目标是提高公开页面正文命中率，不保证平台级完整还原；遇到需要登录、强风控、评论区/楼层、深层懒加载、多段展开或复杂页面结构时，仍应优先引导用户切换手动/OCR 补录。
