# 已完成版本功能总览 (v0.0.1 - v0.0.3)

本文档汇总了截止 v0.0.3 版本，系统已具备的核心能力与技术实现状态。

## 1. 核心业务能力
- **AI 行程生成**：基于 LLM (OpenAI/Ollama) 根据用户输入（目的地/天数/偏好）自动生成结构化每日行程。
- **多轮对话交互**：支持自然语言修改行程（如“帮我把第三天改成去环球影城”、“删掉这个景点”），具备上下文记忆与实体抽取能力。
- **可视化地图**：
  - 基于 Folium 生成交互式地图，支持按天分层展示、路线绘制。
  - POI（兴趣点）自动打点与详情弹窗。
- **RAG 增强检索**：
  - 支持联网搜索（SearXNG）获取实时景点信息与评论。
  - 支持网页抓取与向量化检索，用于补充行程生成的上下文证据。

## 2. 技术架构现状 (v0.0.3)
### 2.1 Agent 编排
- **模式**：Plan-and-Execute (Planner → Checker → Optimizer → Map/RAG)。
- **实现**：
  - **核心**：基于 Python 代码的自研顺序调度 (Scheduler)，具备事件总线 (EventBus) 与状态快照 (SnapshotStore)。
  - **LangGraph 集成**：v0.0.3 版本已集成 LangGraph 基础框架，**在此基础上实现了 `AgentState` 状态定义与 `StateGraph` 基础流转逻辑的验证**；后续将基于此模版替换自研调度器，升级为原生的图编排与持久化架构。
- **调试**：提供 Streamlit 调试面板，可查看 Agent 执行步骤与中间状态。

### 2.2 工具调用 (Function Call)
- **机制**：统一工具协议，支持本地工具与 Function Calling。
- **已集成工具**：
  - `weather.get_daily`: 获取天气预报。
  - `geo.geocode`: 获取目的地经纬度。
  - `poi.search`: 搜索具体 POI 信息（名称/坐标）。

### 2.3 RAG 检索链路
- **流程**：Query -> Search (SearXNG) -> Filter (CrossEncoder) -> Crawl (HTML) -> Vector Store (Chroma) -> Retrieve。
- **特点**：
  - **临时性**：每次生成行程前临时构建向量库，生成后即丢弃（无持久化）。
  - **证据展示**：前端支持展示检索到的来源与摘要，作为生成的“证据”。

### 2.4 前端 UI
- **React + Vite**：作为 v0.0.4 的主力 UI，已完成基础框架搭建与单次生成接口对接。
- **Streamlit**：作为 v0.0.1-v0.0.3 的原型验证 UI，包含调试面板，后续不再维护。
