# v0.0.2

目标：在最小化MVP的基础上，集成主流技术和交互

> 注：在弄清楚技术原理的基础上使用已经有的成熟轮子，不要自己造轮子，可以二次开发！！！！！！！


## 核心需求
1. frontend: 实现前端对话式更新行程
2. rag: 爬虫优化，提高数据采集稳定性
3. llm: LLM 双模式支持（线上 + 本地）
4. map: 多地图切换 + POI 样式定制:基于 CSS Sprite+SVG，实现轻量、清晰的分类渲染 + POI 层级渲染：通过四叉树实现按需渲染，避免遮挡与卡顿


## frontend
1. 实现前端多轮对话交互
- 处理新消息：获取现有核心实体 + 增量提取核心实体 + 添加新消息到短期窗口 + 检查是否需要压缩早期对话（对话转化为长期摘要存入数据库） + 更新短期存储
- 动态优化上下文：prompt如果过长则进行对话内容的缩减：核心实体 > 最近3轮 > 长期摘要 > 早期对话
- 数据保存：保存历史的对话信息，在下一次加载时自动恢复对话内容
> 存储完整的对话历史（用户 + 助手）
> 从用户消息中提取核心实体
> 对长期对话进行压缩和摘要（用户 + 助手）
> 为 LLM 提供优化后的上下文


## rag

### 核心功能
- 意图识别: 使用Sentence-BERT + LLM双阶段意图识别
- 多源搜索: SearXNG聚合多搜索引擎 + 意图特定来源
- 质量过滤: MiniLM重排序 + 权威性/时效性评估 + 综合评分
- 回答生成: 意图自适应prompt模板 + 引用标注 + 冲突消解

### 性能优化
- 缓存机制: 对高频查询结果进行缓存
- 异步处理: 内容提取和质量评估异步执行
- 批量处理: 支持批量查询优化资源利用率
- 动态阈值: 根据查询复杂度动态调整质量阈值

### 实现功能总结
- 深度整合技术栈: 充分利用了SearXNG、Sentence-BERT、MiniLM、ChromaDB、FAISS、Scrapy、BeautifulSoup等技术
- 意图驱动架构: 根据不同意图类型动态调整搜索策略和回答生成
- 质量控制机制: 实现了权威性、时效性、相关性、内容质量的多维度评估
- 工程优化: 包含缓存、异步处理、批量操作等性能优化
- 可扩展设计: 模块化架构便于后续功能扩展和维护
