# v0.0.2

目标：在最小化MVP的基础上，集成主流技术和交互

> 注：在弄清楚技术原理的基础上使用已经有的成熟轮子，不要自己造轮子，可以二次开发！！！！！！！


## 核心需求
1. frontend: 实现前端对话式更新行程
2. rag: 爬虫优化，提高数据采集稳定性
3. llm: LLM 双模式支持（线上 + 本地）
4. map: 多地图切换 + POI 样式定制:基于 CSS Sprite+SVG，实现轻量、清晰的分类渲染 + POI 层级渲染：通过四叉树实现按需渲染，避免遮挡与卡顿


## frontend
1. 实现前端多轮对话交互
- 上下文管理与压缩
- 会话管理: 持久化 + 多设备同步

## rag
### 联网搜索
1. 调研目前主流大模型【网络搜索】的技术方案: 提高数据采集稳定性 + 数据清理，只存储有意义的数据
2. 优化数据采集存储和实时查询的逻辑交互（不是每一次采集都得存储）
3. 支持多轮对话多次采集数据并且筛掉之前已经搜索过的网络地址
### 搜索+上传文档存入向量数据库 + 检索
1. 引入ES支持关键词匹配（query + bool) + 语义匹配（knn) + rank（RRF）来对采集的数据进行高效检索
2. 并行检索优化： 如何在前端并发请求多个 RAG 检索源（如 ES、Milvus），并对结果进行优化聚合。 
3. 流式 UI/UX： 除了基本的 SSE/WebSocket，研究如何通过 Token Streaming 实时渲染，并加入 Source Grounding (来源归因) 的 UI 提示，提升用户信任。
> 后期集成RagFlow，将爬虫数据存储到RagFlow进行检索 + 允许用户在RagFlow中上传文档进行检索

## llm
1. 实现`functionCall`进行天气API的调用，获取每一天行程的天气情况，作为行程规划的参考
2. 实现`Multi-agent`的开发方式进行问题的解决

## map
1. 调研目前免费的地图集成方案，比如mapbox，比如高德地图
