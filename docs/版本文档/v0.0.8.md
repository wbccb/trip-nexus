# TripNexus v0.0.8

## 本版本建议聚焦

- 模仿NotebookLLM进行文档的解析，侧重于文档解析（包括在线和本地文档）的能力，然后进行LLM的行程生成
- v0.0.8 建议承接 v0.0.6 的“约束输入 + 冲突检测 + 替代方案”能力，重点补齐**冲突判定准确性**，而不是继续扩展展示层复杂度。

### 建议纳入

#### 1. 接入真实地图距离/时长 API 做精确校验（建议 P1）

- **必要性评估**：高
  - 当前冲突检测中的 `distance_time` 主要依赖 `city/address/transport` 文本规则与启发式估算，适合 P0 可解释性，但不适合继续承担“强约束判定”的职责。
  - 如果后续要把冲突检测结果作为“是否推荐执行该方案”的核心依据，就需要更稳定的真实路由数据支撑，否则会持续出现误报/漏报。
  - 该能力会直接提升：
    - 跨城冲突判断准确率
    - 单日交通负担判断可信度
    - 替代方案生成时的约束质量

- **建议范围**
  - 为相邻 POI 增加真实路由时长/距离估算，优先覆盖：
    - 驾车时长
    - 公交/地铁时长
    - 步行距离
  - 对 `distance_time` 冲突从“文本规则优先”升级为“地图路由优先，文本规则兜底”。
  - 保留现有轻量规则，作为地图 API 失败时的降级路径。

- **建议修改点**
  - `src/map/map_renderer.py`
    - 复用或扩展已有地理能力，提供 POI 间距离/时长估算接口。
  - `src/llm/llm_manager.py`
    - 在 `_detect_conflicts()` 中接入真实路由判断，替换当前纯文本启发式。
  - `src/api/app.py`
    - 在 finalize payload 中补充可选路由摘要字段，便于前端解释冲突来源。

- **验收标准**
  - 对“单日跨城”“连续远距离 POI”“超长步行”三类场景，冲突结果与真实地图路由基本一致。
  - 地图 API 异常时，主流程不中断，自动回退到现有规则检测。

### 不建议纳入

#### 2. 保留“原方案 vs 已采用方案”的历史对比视图（当前不建议进入 v0.0.8）

- **必要性评估**：低
  - 当前用户已经可以完成“识别冲突 -> 查看替代方案 -> 采用新方案”的核心闭环。
  - 历史对比视图主要提升的是决策体验和可解释性，不是当前主链路的稳定性瓶颈。
  - 该需求会引入额外复杂度：
    - 原方案与已采用方案的双份状态管理
    - 前端差异高亮与地图联动
    - 持久化版本语义与回滚逻辑

- **建议处理方式**
  - 暂不作为 v0.0.8 正式需求。
  - 若后续确实需要增强解释性，优先做轻量版：
    - “本方案主要改动摘要”
    - “第 2 天移除跨城 / 新增午休 / 降低单日景点数”
  - 只有在用户明确需要“版本比较/方案审阅”能力时，再升级为完整历史对比视图。
