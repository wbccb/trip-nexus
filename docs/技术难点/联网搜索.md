# 联网搜索
1. 用户意图解析和搜索指令的生成：将用户的问题转化为搜索引擎可理解的查询语句
2. 搜索引擎调用和结果抓取：将优化后的查询语句发送至搜索引擎，获取原始结果 + 结果筛选 + 内容抓取（对筛选后的网页进行全文爬取）
3. 信息处理和可信度评估：从海量文本中提取可靠信息，解决冲突或矛盾的内容（文本摘要、来源可信度打分、冲突消解）
4. 信息整合和生成回答：将外部信息与内部知识库结合构建prompt，生成自然语言回答

> 一般先进行用户意图的解析 => 判断需要联网搜索

## 1. 用户意图解析和搜索指令的生成
- 意图识别：分析用户问题类型，判断是否需要联网检索
- 关键词提取：可能需要实体识别（NER）技术辅助获取核心关键词
- 查询语义优化：生成适合搜索引擎的查询指令

## 2. 信息处理和可信度评估

### 2.1 搜索结果处理流程
* 初步筛选：通过相关性排序算法（如 BM25）过滤低质量内容，腾讯云向量数据库 Tencent Cloud VectorDB 可辅助语义匹配。
* 内容提取：使用网页解析技术从 URL 中提取完整的网页内容，包括文本、图片、链接等信息。
* 质量评估：基于多维度指标对提取的内容进行质量评估，包括权威性、时效性、相关性、完整性等。
* 信息整合：将多个来源的信息进行综合分析，识别冲突信息并进行验证，最终形成统一的知识表示。
### 2.2 质量控制机制
* 来源可信度评估：建立来源可信度评分体系，优先选择权威网站（如政府官网、知名媒体、学术机构）的信息。
* 时间戳验证：检查信息的发布时间，优先使用最新的信息，特别是对于时效性要求高的内容（如新闻、股价、天气等）。
* 一致性检查：对比多个来源的信息，识别并处理不一致的内容，必要时进行进一步搜索验证。
* 格式标准化：将不同来源的信息转换为统一的格式，便于后续的存储和使用。
* 安全过滤：对提取的内容进行安全检查，包括敏感信息过滤、恶意链接检测等，确保用户安全。


## 3. 多个大模型简单分析
### 3.1 通义千问
- 搜索引擎：阿里自研的搜索技术栈
- 联网搜索筛选机制(三级筛选流程)：
  - 粗筛：BM25 算法过滤低相关性内容，保留 5000 篇候选文档
  - 精筛：稠密向量重排（基于阿里云向量数据库），筛选 100 篇高质量文档
  - 终筛：多维度质量评估，最终保留 20 篇喂给 LLM
  - 时效性：优先选择 24 小时内发布的内容（新闻类）
  - 权威性：政府官网、知名媒体权重 + 30%
  - 结构化：优先选择表格、列表等易解析格式

### 3.2 豆包
- 搜索引擎：火山引擎的搜索接口
- 深度思考模式：动态拆解用户问题并多次调用搜索工具，基于每一次的思考结果进行多次搜索
- GEO生成式引擎优化
  - 意图解析：将用户查询拆解为结构化检索维度
  - 知识抓取：通过搜索引擎抓取关联内容
  - 语义筛选：基于相关性、权威性、结构化程度过滤内容
  - 结构易读性：采用"问题-证据-结论"三段式结构的内容进行思维链推理

### 3.3 文言一心
- 百度搜索引擎
- 知识图谱提供结构化信息的展示

### 3.4 Claude
- Anthropic 自身的搜索服务
- Claude 采用独特的 Constitutional AI 技术，在搜索过程中能够遵循用户设定的价值观和原则，确保搜索结果符合道德和法律要求

### 3.5 Gemini
- 基于 Google Search 的实时信息获取
- 原生多模态架构特别是视频理解能力（Video-MMMU 87.6%）、与 Google 生态的深度整合

### 3.6 GPT-4（OpenAI）
- Bing Search API 实现网页搜索功能
- 混合专家 (MoE) 架构将 GPT-4 划分为 16 个专家子网络，通过动态路由实现计算资源优化


## 4. 搜索引擎可选

### 4.1 搜索引擎API方案
- 全球覆盖 → Google
- 中文优化 → 百度/通义千问
- AI优化 → Tavily
- 隐私保护 → DuckDuckGo

### 4.2 开源方案
- SearXNG：开源、免费 
  - 优势：
    - ✅ 开源免费：MIT许可证，可商用，无API调用成本
    - ✅ 多搜索引擎集成：支持Google/Bing/Baidu等50+搜索引擎
    - ✅ 隐私保护：不追踪用户，适合旅游场景的隐私敏感
    - ✅ 可扩展性强：插件系统支持自定义爬虫和数据源
    - ✅ 部署简单：Docker一键部署，资源占用低
  - 不足：
    - ❌ 缺少AI增强功能（意图识别、查询改写等）
    - ❌ 没有内置RAG流程
    - ❌ 缺少旅游垂直领域的优化
  
- rag-search（个人AI产品）: https://github.com/thinkany-ai/rag-search
  - 优势：完整的联网检索+RAG的功能
  - 不足：缺乏维护，商业化产品目前停滞没有开发，开源部分也没有更新了
> https://www.53ai.com/news/gerentixiao/2024062982409.html
> https://idoubi.cv/blogs/ai-solo-dev

## 5. 最终选择方案

1. 搜索基础： SearXNG + rag-search
2. AI增强：Sentence-BERT + MiniLM
3. 向量存储：ChromaDB + FAISS
4. 爬虫框架：Scrapy + BeautifulSoup
